Welcome to the HumHub content API reference, v2.

These endpoints are part of HumHub core (1.20+). The optional REST API module contributes the token authentication methods they accept and owns the older /api/v1 surface, which is documented with that module. For the design of this stack see docs/develop/concept-api.md.

Conventions of this API generation, differing from /api/v1:

  • Timestamps are ISO-8601 with offset, in UTC (2026-08-22T08:00:00+00:00).
  • Field names are camelCase throughout.
  • Errors are plain HTTP status codes with a JSON body; there is no {code, message} success/failure envelope.

This document covers the context menu of a content record — the data behind the ⋮ menu a stream entry or a module's own list shows. It is deliberately its own endpoint rather than part of any content payload: everything it returns depends on who is asking, so folding it into a record shape would make that shape uncacheable and different for every reader. The same split the comment API makes with GET /comment/{id}/permissions.

Requests may authenticate with any token method the REST API module offers. HumHub's own browser session is accepted too for these endpoints, which is what the platform's Vue UI uses; state-changing session requests additionally require the CSRF token.

The context menu of a content record

Resolves the record's WallEntryControls widget stack — every WallEntryControls::EVENT_INIT handler included — and returns it as data instead of markup, together with what the caller may do with the record.

This is what the ContentControls Vue island loads when its menu is opened, and it is why a module that has contributed a control link for years keeps working in a client-rendered menu without any change: entries that can describe themselves (humhub\modules\ui\menu\DescribableWidget) arrive as descriptors, and only those that cannot fall back to the deprecated html escape hatch.

Loaded lazily, on menu open — a list of 50 rows costs no request at all until someone actually opens a menu.

path Parameters
id
required
integer

The content id — the primary key of the content record, not the primary key of the owning model (a post, a file, an event).

query Parameters
viewContext
string
Enum: "default" "dashboard" "search" "detail" "modal"

Where the menu is being shown. Selects the render-options profile a server-rendered menu would have used in the same place, so a menu inside a module's own UI is not offered stream-only actions. Omit for the default profile.

suppress
string
Examples:
  • suppress=edit,move,delete - A file browser rendering its own Edit/Move/Delete

Comma-separated list of core entries the caller renders itself and does not want from the server. A host with its own Edit action would otherwise receive a second, server-rendered one next to it.

Unknown names are ignored.
